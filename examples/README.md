# 示范题

三个可运行的交互题样板，覆盖交互自测的三种形态。用法：把整个文件夹复制到
`workspace/` 下（应用会自动在启动时扫描到），或者直接点「🔀 交互器」里的运行按钮。

| 目录 | 演示什么 | 怎么跑 |
|---|---|---|
| `示范-1-手动对答` | 没有交互器时人工扮演交互器 | 交互器标签 → 切到「手动对答」→ 开始；程序输出 `50` 后，按答案 42 依次输入 `3 2 2 3 2 2 1` |
| `示范-2-testlib` | testlib 最简写法（`inf/tout/ouf/quitf`） | 交互器标签 →「用交互器」→ 运行交互自测 |
| `示范-3-矩阵猜序列` | 大块矩阵输出 + 随机打乱行序 + 还原排列 | 交互器标签 →「用交互器」→ 运行交互自测 |

## 交互协议约定

自测运行器对交互器有两条约定，两种写法都支持：

**普通写法**（自己 cin/cout）

```
argv[1] = 测试数据文件
stdout  = 发给选手（接到选手的 stdin）
stdin   = 读选手输出（来自选手的 stdout）
退出码 0 = AC，非 0 = WA
```

**testlib 写法**（`#include "testlib.h"` + `registerInteraction`）

```
argv[1] = 输入文件（inf）
argv[2] = 输出通道（tout，运行时被换成管道/文件）
stdin   = 选手输出（ouf）
quitf(_ok/_wa) 决定判定
```

`testlib.h` 已随应用内置（`src-tauri/resources/testlib/`），不用自己准备。

## 注意

- 交互器往选手发东西后，**必须 flush**（`endl` 或 `cout.flush()` / `tout << endl`），否则对面收不到，会一直等到超时。
- 大数据（比如 n=9999 的矩阵）建议用 `ostringstream` 拼好一次性写出，别每个数 flush 一次。
